# MoMo Market API

## Run locally

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Fill the three MoMo credential values in `.env` before testing a real payment. The server will not send provider requests until those values are set.

## API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health` | Server and MoMo configuration check |
| POST | `/api/auth/login` | Demo login placeholder |
| GET | `/api/products?q=` | Product catalogue/search |
| POST | `/api/ai/product-description` | Description generator |
| GET | `/api/merchant/dashboard` | Merchant metrics + insight |
| POST | `/api/payments/momo` | Creates a MoMo Collection request-to-pay |
| GET | `/api/payments/momo/:referenceId` | Gets provider payment status and confirms order on success |
| GET | `/api/orders/:paymentReference` | Returns confirmed order |

### Initiate payment example

```json
{
  "amount": 499,
  "currency": "ZAR",
  "payerMsisdn": "27812345678",
  "externalId": "cart_123",
  "items": [{ "productId": "earphones", "quantity": 1 }]
}
```

`GET /api/payments/momo/:referenceId` must return `SUCCESSFUL` before treating an order as confirmed. The MoMo reference is generated by the server as a unique UUID.

## Production hardening before launch

- Replace demo auth with verified identity, password hashing, and sessions/JWT rotation.
- Store products, payments, and orders in PostgreSQL rather than in-memory Maps.
- Add authentication/authorisation middleware to merchant endpoints.
- Restrict CORS to the deployed frontend URL.
- Add rate limits, logs with secret redaction, idempotency controls, and webhook processing if enabled by the provider.
