# MoMo Market API

## Run locally

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Fill `MOMO_API_USER`, `MOMO_API_KEY`, and either `MOMO_COLLECTION_SUBSCRIPTION_KEY` or the legacy `MOMO_SUBSCRIPTION_KEY` in `.env` before testing a real payment. The server will not send provider requests until those values are set. In the Postman collection, `api_key` is the Basic-auth password; this integration does not require a separate `MOMO_API_SECRET`.

## Postman

Import `../postman/MoMo Market.postman_collection.json` and `../postman/Production SA.local.postman_environment.json`. Run `Create MoMo Payment` first, then copy its `referenceId` into the environment variable `payment_reference` before running `Get MoMo Payment Status`. The local environment is ignored by git because it contains credentials.

## API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health` | Server and MoMo configuration check |
| POST | `/api/auth/login` | Demo login placeholder |
| GET | `/api/products?q=` | Product catalogue/search |
| GET | `/api/products?category=Home-grown` | Home-grown produce, including spinach, peanuts and lettuce |
| GET | `/api/products?category=Spaza%20shop` | Products sold by neighborhood spaza shops |
| POST | `/api/ai/product-description` | Description generator |
| GET | `/api/merchant/dashboard` | Merchant metrics + insight |
| POST | `/api/payments/pay` | Creates a MoMo Collection request-to-pay (`/api/payments/momo` remains supported) |
| GET | `/api/payments/momo/:referenceId` | Gets provider payment status and confirms order on success |
| GET | `/api/orders/:paymentReference` | Returns confirmed order |

### Initiate payment example

```json
{
  "amount": 499,
  "currency": "ZAR",
  "phoneNumber": "27812345678",
  "externalId": "cart_123",
  "items": [{ "productId": "earphones", "quantity": 1 }]
}
```

`GET /api/payments/momo/:referenceId` must return `SUCCESSFUL` before treating an order as confirmed. The MoMo reference is generated by the server as a unique UUID.

Marketplace categories include `Home-grown` for local growers and `Spaza shop` for neighborhood retailers. Product listings can include a `unit` such as `250 g`, `1 bunch`, or `1 head` so produce pricing is clear.

MoMo credentials and access tokens are used only by the backend. The frontend calls `/api/payments/pay`; it never receives the API user, API key, subscription key, or access token.

## Production hardening before launch

- Replace demo auth with verified identity, password hashing, and sessions/JWT rotation.
- Store products, payments, and orders in PostgreSQL rather than in-memory Maps.
- Add authentication/authorisation middleware to merchant endpoints.
- Restrict CORS to the deployed frontend URL.
- Add rate limits, logs with secret redaction, idempotency controls, and webhook processing if enabled by the provider.
